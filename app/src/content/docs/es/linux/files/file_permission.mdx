---
title: Permisos de Archivos
description: CheatSheet - Permisos de Archivos y Directorios en Linux
---

En Linux y Unix, **todo se considera un archivo**, incluyendo directorios y dispositivos. Todos los archivos en un sistema tienen permisos que gobiernan el acceso y las posibles acciones por diferentes tipos de usuarios. Estos permisos, a menudo llamados "bits", están asociados con la propiedad del archivo. El superusuario "**root**" tiene la capacidad de acceder a cualquier archivo en el sistema. Para modificar archivos pertenecientes a `root`, el uso de `sudo` es necesario.

---

## Tipos de Restricciones de Acceso (Permisos)

Hay tres tipos principales de restricciones de acceso (permisos) que definen lo que los usuarios pueden hacer con un archivo o directorio.

| Permiso | Descripción | Valor |
|---------|-------------|-------|
| **Lectura** (`r` o `4`) | En un **archivo**: Permite acceder al contenido del archivo (leer texto, ver medios). En un **directorio**: Permite listar el contenido del directorio (`ls`), pero no acceder a él (a menos que también esté presente el permiso de ejecución). | 4 |
| **Escritura** (`w` o `2`) | En un **archivo**: Permite modificar el contenido del archivo. Nota: el permiso de escritura en un *directorio* permite eliminar archivos en ese directorio, incluso si el usuario no tiene permisos de escritura en el archivo en sí. En un **directorio**: Permite modificar el contenido del directorio, crear o eliminar archivos o subdirectorios dentro de él (también requiere permiso de ejecución). | 2 |
| **Ejecución** (`x` o `1`) | En un **archivo**: Permite ejecutar scripts y aplicaciones. En un **directorio**: Permite "cambiar" al directorio (`cd`) y usar los archivos/subdirectorios que contiene. **Los directorios deben tener necesariamente el permiso de 'ejecución' para funcionar correctamente**. | 1 |

Estos permisos a menudo se representan mediante una serie de 9 caracteres (`rwxrwxrwx`) o en notación octal (tres números del 0 al 7). Un guión (`-`) indica la ausencia del permiso.

---

## Tipos de Restricciones de Usuarios (Propiedad)

Los permisos se aplican a tres categorías de usuarios:

| Categoría | Descripción | Símbolo |
|----------|-------------|-------|
| **Propietario** | El usuario que posee el archivo, típicamente su creador. | `u` |
| **Grupo** | El grupo de usuarios que posee el archivo. Un usuario que es miembro de este grupo puede tener ciertos permisos específicos en el archivo. | `g` |
| **Otros** | Todos los demás usuarios que no son ni el propietario ni miembros del grupo propietario. | `o` |

La visualización detallada de una lista de archivos (`ls -l`) muestra estos permisos en la forma `-rwxr-xr-x`, donde el primer carácter indica el tipo de archivo, seguido de 3 caracteres para el propietario, 3 para el grupo, y 3 para otros.

## Gestión de Permisos (`chmod`)

El comando `chmod` se utiliza para modificar los permisos de acceso de un archivo o directorio. El uso de `sudo` es a menudo necesario para modificar los permisos de archivos que el usuario no posee.

### Métodos para Modificar Permisos

| Método | Descripción | Ejemplo |
|--------|-------------|--------|
| **Usando letras** | Usa códigos para usuarios (`u`, `g`, `o`, `a` para todos) y permisos (`r`, `w`, `x`), combinados con `+` (añadir), `-` (eliminar), o `=` (establecer). | `chmod u+x archivo1` |
| **Usando números (Octal)** | Representa los permisos de lectura (4), escritura (2) y ejecución (1) mediante números. Estos valores se suman para cada categoría (propietario, grupo, otros) para obtener un número de tres dígitos. | `chmod 755 directorio` |

### Ejemplos de Comandos

| Comando | Descripción |
|---------|-------------|
| `chmod u+x archivo1` | Añade el permiso de ejecución para el propietario. |
| `chmod g-r archivo3` | Elimina el permiso de lectura para el grupo. |
| `chmod u=rw,go=r miArchivo` | Establece rw para el propietario y r para el grupo/otros. |
| `chmod 755 directorio` | Establece rwx para el propietario y r-x para el grupo/otros. |
| `chmod 644 archivo` | Establece rw- para el propietario y r-- para el grupo/otros. |
| `chmod 667 nombreArchivo` | Establece rw- para el propietario y grupo, y rwx para otros. |

## Modificación Recursiva de Permisos

Para modificar los permisos de múltiples archivos y directorios bajo una ruta dada:

| Comando | Descripción |
|---------|-------------|
| `chmod -R` | Aplica los permisos de manera recursiva a todos los archivos y subdirectorios. |
| `find` y `chmod` | Permite una aplicación más selectiva combinando el comando `find` con `chmod`. |

### Ejemplos de Comandos Recursivos

| Comando | Descripción |
|---------|-------------|
| `sudo chmod 777 -R /ruta/al/directorio` | Aplica los permisos 777 de manera recursiva. |
| `sudo find /ruta/al/directorio -type f -print0 | xargs -0 sudo chmod 644` | Aplica los permisos 644 solo a archivos. |
| `sudo find /ruta/al/directorio -type d -print0 | xargs -0 sudo chmod 755` | Aplica los permisos 755 solo a directorios. |

> **ADVERTENCIA**: Los comandos recursivos, especialmente combinados con `sudo`, son extremadamente peligrosos. Un error tipográfico puede llevar a la eliminación o modificación de permisos de archivos críticos del sistema. ¡Ten mucho cuidado!

## Cambio de Propietario y Grupo

| Comando | Descripción | Ejemplo |
|---------|-------------|--------|
| `chown` | Permite cambiar el propietario de un archivo o directorio. También puede cambiar el grupo propietario. | `sudo chown usuario_objetivo archivo` |
| `chgrp` | Permite específicamente cambiar el grupo propietario de un archivo o directorio. | `sudo chgrp grupo_objetivo archivo` |

### Ejemplos de Comandos

| Comando | Descripción |
|---------|-------------|
| `sudo chown usuario_objetivo:grupo_objetivo archivo` | Cambia el propietario y el grupo. |
| `sudo chown :grupo_objetivo archivo` | Cambia solo el grupo. |
| `sudo chgrp grupo_objetivo archivo` | Cambia el grupo propietario. |
| `sudo chown -R usuario_objetivo:grupo_objetivo /ruta/al/directorio` | Cambia recursivamente el propietario y el grupo. |

Por defecto, el uso de `sudo` es requerido para cambiar el propietario o grupo de un archivo.

## Permisos por Defecto (`umask`)

Cuando se crea un nuevo archivo o directorio, automáticamente obtiene permisos por defecto. Este comportamiento está determinado por un parámetro llamado la **máscara de usuario** (`umask`).

| Concepto | Descripción |
|---------|-------------|
| **Valor por defecto de `umask`** | A menudo `022` en Ubuntu. |
| **Permisos por defecto** | `644` (`rw-r--r--`) para **archivos** y `755` (`rwxr-xr-x`) para **directorios**. |
| **Modificación de `umask`** | Puede ser modificado para la sesión actual (`umask 007`), para un usuario específico (`~/.bashrc` o `~/.profile`), o globalmente (`/etc/profile` o `/etc/pam.d/common-session` - desaconsejado globalmente). |

Los sistemas de archivos compatibles con POSIX (como ext4) gestionan los permisos directamente en el sistema de archivos. Para sistemas de archivos no compatibles con POSIX (como FAT/NTFS), los permisos son emulados en el momento del montaje y definidos por las opciones de montaje (`mount -o`).

## El Sticky Bit

El sticky bit es un permiso especial que se aplica principalmente a directorios, típicamente aquellos accesibles en escritura por "otros" (como `/tmp`).

| Concepto | Descripción |
|---------|-------------|
| **Sticky Bit** | Cuando está activado en un directorio, el sticky bit **impide que los usuarios eliminen o renombren archivos que no poseen personalmente** en ese directorio. |
| **Configuración** | Se establece o elimina usando `chmod` con el indicador `t`: |
| | Añadir: `chmod +t <directorio>`. |
| | Eliminar: `chmod -t <directorio>`. |

En la visualización detallada de `ls -l`, la presencia del sticky bit se indica con una `t` o `T` en lugar del bit de ejecución para "otros".

## Otros Conceptos Relacionados

| Concepto | Descripción |
|---------|-------------|
| **ACL (Lista de Control de Acceso)** | Un método para lograr una granularidad de permisos más fina que los permisos Unix estándar. Esto requiere la instalación del paquete `acl` y la activación de la opción `acl` en `/etc/fstab`. Los comandos `setfacl` y `getfacl` se utilizan para gestionar las ACLs. |
| **Gestión de Usuarios y Grupos** | Comandos como `adduser`, `addgroup`, `useradd`, `groupadd`, `userdel`, `deluser`, `usermod`, `passwd`, `groups` se utilizan para gestionar usuarios y grupos. Son fundamentales ya que definen los usuarios y grupos a los cuales se asignan los permisos. Estos comandos modifican archivos críticos del sistema como `/etc/passwd`, `/etc/shadow`, y `/etc/group`. |
