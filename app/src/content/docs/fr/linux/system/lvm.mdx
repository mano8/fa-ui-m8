## 1. **What is LVM and why use it?**

LVM, or **Logical Volume Manager**, is a system that enables **flexible and dynamic management of disk partitions under Linux**.

With LVM, you can **create, modify, delete, or resize logical partitions** without concern for their physical location on the disk. You can also **combine multiple disks or partitions into a single logical volume**, or create **snapshots** of your data for easy backups.

In this article, we will show you how to **modify the disk space of an LVM partition** in a few simple steps. Whether you are a beginner or an expert, you will discover how LVM can simplify your life and optimize your system.

---

## 2. Adding disk space to a virtual machine.

To add disk space to a virtual machine, you need to access its **configuration options**.

**Important note**: the virtual machine must be **powered off**.

![open virtual machine configuration menu](/img_docs/lvm/Workstation_player_vm_settings.jpg)

Once in the configuration settings, locate the disk configuration and click the "**Expand**" button.

![virtual machine configuration menu](/img_docs/lvm/es_Workstation_player_vm_hard_disk_settings_expand.jpg)

This will open a new window where you can **increase the disk size**. However, as indicated, this will only expand the virtual disk size **without affecting the existing partitions**.

![Expand virtual machine disk space](/img_docs/lvm/es_Workstation_player_vm_hard_disk_settings_expand_menu.jpg)

Once the virtual disk is expanded with the desired amount of memory, we will need to **re-partition the virtual disk**.

## 3. Allocate disk space to the main partition

Now, we can allocate the disk space to our **primary partition**. There are several possible methods.

### 3.1 Adding a disk to a virtual machine

If you wish to use a **graphical interface** to re-partition your virtual disk, and the virtual machine in question does not have a graphical interface, you can use another virtual machine with a graphical interface, or boot a live CD on your virtual machine.

Here we will use an existing **Linux Mint** virtual machine as an example. First, we need to add our virtual disk (which we just modified) to it. To do this, go to the **configuration menu of the virtual machine** (Linux Mint here).

![Adding a device to a virtual machine](/img_docs/lvm/es_Workstation_player_vm_settings_add.jpg)

Add a **new disk**, and click next. Then choose the corresponding disk type (SCSI by default).

![Adding a disk to a virtual machine](/img_docs/lvm/es_Workstation_player_vm_settings_add_view_1.jpg)

Next, you need to choose the "**Add an existing disk**" option, then next. Afterward, select the file corresponding to the virtual disk you are interested in (here, the disk where we added space and that needs to be re-formatted). Finally, click the "**Finish**" button.

![Adding an existing disk to a virtual machine](/img_docs/lvm/es_Workstation_player_vm_settings_add_existing_hard_disk.jpg)

### 3.2 Using GParted

Now, the virtual disk we wish to re-partition appears in the list of devices. We can close the window and start the virtual machine (Linux Mint here). Once started, open the **GParted** application, and choose the disk to re-partition (generally `/dev/sdb` for a standard installation).

![Using GParted](/img_docs/lvm/es_vm_gparted_expand_view_0.jpg)

Here, the disk space we added previously (**20 GB** in my case) appears as **unallocated**, which is normal. We will need to resize the main partition (`sdb3`) to add the unallocated disk space to it. To do this, right-click on the main partition (`sdb3` here) and choose the "**Resize/Move**" option. Then, in the new window, resize the partition so that the following free space is equal to 0. This will increase our main partition by an additional 20 GB.

![Resize a disk in GParted](/img_docs/lvm/es_vm_gparted_expand_view_2.jpg)

Finally, you must **confirm the changes** for them to take effect. However, since the main partition is LVM, there is still one last step for this to be effective.

### 3.3 Extending the logical volume

To extend our LVM to the entire free disk space, we will use the **command prompt**.

First, the `lsblk` command gives us an overview of the current state of the partitions:

```bash
user@user:~$ lsblk
NAME               MAJ:MIN RM   SIZE RO TYPE MOUNTPOINTS
sda                  8:0    0    60G  0 disk 
├─sda1               8:1    0     1M  0 part 
├─sda2               8:2    0   513M  0 part /boot/efi
└─sda3               8:3    0  59.5G  0 part /
sdb                  8:16   0   100G  0 disk 
├─sdb1               8:17   0     1M  0 part 
├─sdb2               8:18   0     2G  0 part 
└─sdb3               8:19   0    98G  0 part 
  └─ubuntu--vg-ubuntu--lv 253:0    0    78G  0 lvm  
sr0                 11:0    1  1024M  0 rom
```

Here we see that our `sdb3` partition is **98GB** but the **LVM is only 78GB**. Our system will not have access to all the available disk space here. The **20GB** we just added to our virtual disk are missing.

All the following commands must be executed with **root privileges**.

First, we will list the **logical volumes (LV)** with the command:

```bash
user@user:~$ sudo lvs
  LV          VG        Attr       LSize   Pool Origin Data%  Meta%  Move Log Cpy%Sync Convert
  ubuntu-lv   ubuntu-vg -wi-a----- <78.00g
```

Here there is only one, and that's the one we are going to extend.

If in doubt, we can also list the **physical volumes (PV)**:

```bash
user@user:~$ sudo pvs
PV           VG        Fmt  Attr PSize   PFree 
  /dev/sdb3    ubuntu-vg lvm2 a--  <98.00g 20.00g
```

As well as the **volume groups (VG)**:

```bash
user@user:~$ sudo vgs
  VG          #PV #LV #SN Attr   VSize   VFree 
  ubuntu-vg     1   1   0 wz--n- <98.00g 20.00g
```

This gives us the necessary information for the next operations. In summary, we have:

* **ubuntu-lv**: our logical volume (LV) **78.00 Gb**
* **ubuntu-vg**: our volume group (VG) **98.00 Gb** which contains our logical volume (LV)
* **/dev/sdb3**: our physical volume (PV), **98.00 Gb** disk partition

Here, the partition table data is up to date; our physical volume and our volume group are both **98 GB**.

But in case the physical volume and/or the volume group do not display the correct disk size (are not up to date), we will resize our physical volume (PV):

```bash
user@user:~$ sudo pvresize /dev/sdb3
  Physical volume "/dev/sdb3" changed
  1 physical volume(s) resized or updated / 0 physical volume(s) not resized
```

And finally, we will extend our logical volume to all available free space with the command:

```bash
user@user:~$ sudo lvextend -l +100%FREE /dev/ubuntu-vg/ubuntu-lv
  Size of logical volume ubuntu-vg/ubuntu-lv changed from <78.00 GiB (19967 extents) to <98.00 GiB (25087 extents).
  Logical volume ubuntu-vg/ubuntu-lv successfully resized.
```

Then resize the file system:

```bash
user@user:~$ sudo e2fsck -f /dev/ubuntu-vg/ubuntu-lv
  e2fsck 1.46.5 (30-Dec-2021)
  Pass 1: Checking inodes, blocks, and sizes
  Pass 2: Checking directory structure
  Pass 3: Checking directory connectivity
  Pass 4: Checking reference counts
  Pass 5: Checking group summary information
  /dev/ubuntu-vg/ubuntu-lv: 332341/5111808 files (0.4% non-contiguous), 4872372/20446208 blocs
```

```bash
user@user:~$ sudo resize2fs /dev/ubuntu-vg/ubuntu-lv
  Resizing the file system on /dev/ubuntu-vg/ubuntu-lv to 25689088 (4k) blocks.
  The file system on /dev/ubuntu-vg/ubuntu-lv is now 25689088 blocks (4k) long.
```

And there you have it! All that's left is to shut down this virtual machine and start Ubuntu Server, which will now have an additional **20GB** of available space.
