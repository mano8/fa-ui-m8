title: File Permissions
description: CheatSheet - Linux File and Directory Permissions
---

In Linux and Unix, **everything is considered a file**, including directories and devices. All files on a system have permissions that govern access and possible actions by different types of users. These permissions, often called "bits," are associated with file ownership. The superuser "**root**" has the ability to access any file on the system. To modify files owned by `root`, the use of `sudo` is necessary.

---

## Types of Access Restrictions (Permissions)

There are three main types of access restrictions (permissions) that define what users can do with a file or directory.

| Permission | Description | Value |
|-----------|-------------|-------|
| **Read** (`r` or `4`) | On a **file**: Allows access to the file's content (read text, view media). On a **directory**: Allows listing the directory's content (`ls`), but not accessing it (unless the execute permission is also present). | 4 |
| **Write** (`w` or `2`) | On a **file**: Allows modifying the file's content. Note that write permission on a *directory* allows deleting files in that directory, even if the user does not have write permissions on the file itself. On a **directory**: Allows modifying the directory's content, creating or deleting files or subdirectories within it (also requires execute permission). | 2 |
| **Execute** (`x` or `1`) | On a **file**: Allows running scripts and applications. On a **directory**: Allows "changing" into the directory (`cd`) and using the files/subdirectories it contains. **Directories must necessarily have the 'execute' permission to function correctly**. | 1 |

These permissions are often represented by a series of 9 characters (`rwxrwxrwx`) or in octal notation (three numbers from 0 to 7). A dash (`-`) indicates the absence of the permission.

---

## Types of User Restrictions (Ownership)

Permissions apply to three categories of users:

| Category | Description | Symbol |
|----------|-------------|-------|
| **Owner** | The user who owns the file, typically its creator. | `u` |
| **Group** | The group of users who own the file. A user who is a member of this group may have specific permissions on the file. | `g` |
| **Others** | All other users who are neither the owner nor members of the owning group. | `o` |

The detailed display of a file list (`ls -l`) shows these permissions in the form `-rwxr-xr-x`, where the first character indicates the file type, followed by 3 characters for the owner, 3 for the group, and 3 for others.

---

## Managing Permissions (`chmod`)

The `chmod` command is used to modify the access permissions of a file or directory. The use of `sudo` is often necessary to modify the permissions of files that the user does not own.

### Methods for Modifying Permissions

| Method | Description | Example |
|--------|-------------|---------|
| **Using letters** | Uses codes for users (`u`, `g`, `o`, `a` for all) and permissions (`r`, `w`, `x`), combined with `+` (add), `-` (remove), or `=` (set). | `chmod u+x file1` |
| **Using numbers (Octal)** | Represents the read (4), write (2), and execute (1) permissions by numbers. These values are added for each category (owner, group, others) to obtain a three-digit number. | `chmod 755 directory` |

### Command Examples

| Command | Description |
|---------|-------------|
| `chmod u+x file1` | Adds execute permission for the owner. |
| `chmod g-r file3` | Removes read permission for the group. |
| `chmod u=rw,go=r myFile` | Sets rw for the owner and r for the group/others. |
| `chmod 755 directory` | Sets rwx for the owner and r-x for the group/others. |
| `chmod 644 file` | Sets rw- for the owner and r-- for the group/others. |
| `chmod 667 filename` | Sets rw- for the owner and group, and rwx for others. |

## Recursive Permission Modification

To modify the permissions of multiple files and directories under a given path:

| Command | Description |
|---------|-------------|
| `chmod -R` | Applies permissions recursively to all files and subdirectories. |
| `find` and `chmod` | Allows more selective application by combining the `find` command with `chmod`. |

### Examples of Recursive Commands

| Command | Description |
|---------|-------------|
| `sudo chmod 777 -R /path/to/directory` | Applies permissions 777 recursively. |
| `sudo find /path/to/directory -type f -print0 | xargs -0 sudo chmod 644` | Applies permissions 644 to files only. |
| `sudo find /path/to/directory -type d -print0 | xargs -0 sudo chmod 755` | Applies permissions 755 to directories only. |

> **WARNING**: Recursive commands, especially combined with `sudo`, are extremely dangerous. A typo can lead to the deletion or modification of permissions of critical system files. Be very careful!

## Changing Owner and Group

| Command | Description | Example |
|---------|-------------|---------|
| `chown` | Allows changing the owner of a file or directory. Can also change the owning group. | `sudo chown target_user file` |
| `chgrp` | Specifically allows changing the owning group of a file or directory. | `sudo chgrp target_group file` |

### Command Examples

| Command | Description |
|---------|-------------|
| `sudo chown target_user:target_group file` | Changes the owner and group. |
| `sudo chown :target_group file` | Changes the group only. |
| `sudo chgrp target_group file` | Changes the owning group. |
| `sudo chown -R target_user:target_group /path/to/directory` | Recursively changes the owner and group. |

By default, the use of `sudo` is required to change the owner or group of a file.

## Default Permissions (`umask`)

When a new file or directory is created, it automatically gets default permissions. This behavior is determined by a parameter called the **user mask** (`umask`).

| Concept | Description |
|---------|-------------|
| **Default `umask` value** | Often `022` in Ubuntu. |
| **Default permissions** | `644` (`rw-r--r--`) for **files** and `755` (`rwxr-xr-x`) for **directories**. |
| **Modifying `umask`** | Can be modified for the current session (`umask 007`), for a specific user (`~/.bashrc` or `~/.profile`), or globally (`/etc/profile` or `/etc/pam.d/common-session` - globally discouraged). |

POSIX-compatible file systems (like ext4) manage permissions directly on the file system. For non-POSIX-compatible file systems (like FAT/NTFS), permissions are emulated at mount time and defined by mount options (`mount -o`).

---

## The Sticky Bit

The sticky bit is a special permission that mainly applies to directories, typically those writable by "others" (such as `/tmp`).

| Concept | Description |
|---------|-------------|
| **Sticky Bit** | When activated on a directory, the sticky bit **prevents users from deleting or renaming files they do not personally own** in that directory. |
| **Setting** | It is set or removed using `chmod` with the `t` flag: |
| | Add: `chmod +t <directory>`. |
| | Remove: `chmod -t <directory>`. |

In the detailed display of `ls -l`, the presence of the sticky bit is indicated by a `t` or `T` in place of the execute bit for "others".

## Other Related Concepts

| Concept | Description |
|---------|-------------|
| **ACL (Access Control List)** | A method to achieve finer-grained permissions than standard Unix permissions. This requires the installation of the `acl` package and enabling the `acl` option in `/etc/fstab`. The commands `setfacl` and `getfacl` are used to manage ACLs. |
| **User and Group Management** | Commands such as `adduser`, `addgroup`, `useradd`, `groupadd`, `userdel`, `deluser`, `usermod`, `passwd`, `groups` are used to manage users and groups. They are fundamental as they define the users and groups to which permissions are assigned. These commands modify critical system files such as `/etc/passwd`, `/etc/shadow`, and `/etc/group`. |
